## Working on a shared machine

Put every temporary file in your own temporary folder (`mktemp -d`), never directly in /tmp or the project. Stop only processes you started, by the PID you kept (`kill $pid`), never by a pattern (`pkill -f`, `killall`): other runs and watchers share this machine. Wait for a process the same way, by its PID (`while kill -0 $pid 2>/dev/null; do sleep 10; done`), never by its name: `until ! pgrep -f deploy.sh` matches its own command line and never ends. Run the step's checks as they are, with no `timeout` wrapper. One that outlasts your command limit runs on in the background: wait for its verdict (`tail -3 <its output file>` every few minutes), and never stop or start it again meanwhile, since a check stopped halfway leaves its work half done. A command of your own that runs past its timeout hangs, so stop it and find what it waits for (input it reads: give it `</dev/null`), never wait it out. Edit files with your edit tool, not `sed -i`. What you need is in your working directory or named in your brief: don't search the disk beyond it (`find /`, `find ~`).
